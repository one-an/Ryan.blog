## 我是谁？

我，一个典型的后端生物：

- 写了五年 Java，熟练掌握 `System.out.println` 调试法
- Spring Boot 骨灰级用户，看见 `application.yml` 比看见亲妈还亲
- 深信“没有数据库的应用等于没有灵魂”
- 日常工作是让同事的请求经过 Controller → Service → DAO，然后返回一句 `"ok"`

五年了，我闭着眼睛都能搭出一个 CRUD，快无聊到开始给变量起冷笑话名字了。

所以，我决定搞点事。

## 什么是 Vibecoding？我的理解

Vibecoding，简单说就是：

**关掉需求文档，忘掉排期，跟着感觉走，AI 在旁边递砖，我只负责喊“这很酷”。**

不是为了交付，不是为了 KPI，纯属因为“这个效果真带劲”、“这个交互好丝滑”、“这个技术名词我光听过没用过”。

博客，就是我第一个可以合法发疯的 vibe 项目。

## 一个 Java 后端，为什么要用 Next.js？

如果用 Spring Boot 写博客，我的肌肉记忆大概长这样：

1. 新建 Spring Boot 项目
2. 引入 JPA、Thymeleaf、MySQL
3. 写好 Entity、Repository、Service、Controller
4. 喝杯咖啡，收工。

这叫什么？这叫**把班味儿带回家**。

我不要。我要的是：

- **服务器端渲染，首屏快得像后端的 RPC 调用** → Next.js App Router
- **类型安全，写错了 TypeScript 直接甩脸** → 比 Java 的泛型还上头
- **写样式不用在文件间反复横跳** → Tailwind CSS，一个 className 走天下
- **页面切换来点动画，别跟政府网站似的** → Framer Motion
- **文章里能直接插入自定义组件** → MDX，Markdown 里写 JSX，像在后端模板里写逻辑一样爽
- **后台编辑得有个顺手的 Markdown 编辑器** → @uiw/react-md-editor，颜值在线
- **认证别搞太重，但必须能装一波** → GitHub OAuth + jose 手签 JWT，重新学一遍 OAuth 流程
- **评论系统绝不自己维护** → Giscus，白嫖 GitHub Discussions，数据库都不用建
- **存储返璞归真** → 纯文件系统，.mdx + .json，MySQL 第一次被我冷落在角落里瑟瑟发抖
- **部署方式必须熟悉** → Node.js + Nginx 反代 + PM2，跟部署 Spring Boot 一个味儿，安心

看到没，这就是一个后端最后的倔强：跨了界，但没完全跨。

## Vibecoding 过程中的“至暗时刻”与“高光瞬间”

### 1. 用文件系统当数据库，感觉自己像个田园诗人

没有 MySQL，没有 Redis，甚至 SQLite 都被我嫌弃。文章直接存 `.mdx`，元数据放 `.json`。

好处是什么？备份就是复制粘贴，迁移就是打包带走。版本管理？Git 天生支持。

坏处是什么？嗯……暂时没发现，大概等文章破万篇的时候再考虑吧，反正那天还早。

### 2. 手搓 JWT，终于知道 Spring Security 给我挡了多少子弹

我决定自己用 `jose` 签发和验证 JWT，而不是写几行 `spring.security.oauth2.*` 了事。

于是我又重温了一遍授权码模式：

- GitHub 回调拿 code
- 换 access_token
- 拿用户信息
- 自己造 JWT，塞 cookie 里

全程手动，AI 在旁边时不时提醒我“这儿容易写错”。搞完之后，我对 Spring Security 的敬畏之心增加了十倍。这玩意儿真帮我们干了好多脏活。

### 3. Giscus：这波白嫖，资本家看了都落泪

评论系统直接挂在 GitHub Discussions 上。所有评论都是 Issue 的回复，存储、渲染、通知 GitHub 全包了。

我连数据库都没建，表都没设计。Giscus 就是我见过的**最香的白嫖方案**，没有之一。

### 4. CSS 差点让我秃了，但 Tailwind 救了我

作为一个后端，CSS 一直是我的知识黑洞。每次写样式都像在解高数题，还是没答案那种。

Tailwind 的出现，让我感觉写样式像在拼乐高：`flex items-center justify-between`，行云流水。

当然，第一次看到 HTML 里塞满 class 时，我还是干呕了一下。但很快真香了。

### 5. 部署：熟悉的配方，熟悉的味道

`next start` 跑在 Node.js 上，前面 Nginx 反代挂 SSL，PM2 盯着进程。

我坐在电脑前会心一笑：这不就是 Spring Boot 应用的部署方式吗？换了壳子，灵魂还是那个工程化的灵魂。

那一刻我明白了：工具会变，但后端那种“服务能稳定跑起来就别乱动”的信念永远不会变。

## 一个后端写前端，到底给我带来了什么？

最直接的：**我重新找回了刚入行时写代码的快乐。**

没有需求评审，没有排期，没有“这个性能能不能再优化一下”。想加动画就加，想换布局就换。AI 能迅速帮我把灵感变成原型，然后我再慢慢调成自己喜欢的样子。

而且，我现在跟前端同事聊天，再也不只会说“接口文档更新了，你看一下”。我会说：“这个组件如果拆成 Server Component，首屏能快一点。” 前端看我的眼神都变了。

## 这个博客以后会写什么？

有了这个用 vibe 搓出来的博客，我更想把这种“边玩边学”的过程记录下来：

- **Java 进阶**：JVM 调优、并发编程、Spring 深水区
- **架构复盘**：分布式事务、消息驱动、真实踩坑记录
- **全栈踩坑笔记**：Next.js、React、TypeScript 的血泪史
- **Vibecoding 系列**：如何用 AI 把想法快速变成能跑的项目
- **程序员的自我修养**：五年码农的焦虑、破局和瞎折腾

## 写在最后

如果你也是一名后端，被日复一日的需求压得有点麻木，我强烈建议你：找个周末，开一个自己的 vibe 项目。

不用考虑技术选型是不是最优，不用纠结性能是不是极致。就选你看着最顺眼的技术栈，写点让自己开心的东西。把 MySQL 扔一边，把 Spring Boot 关掉，哪怕只是个跑在 Node.js 上的小博客。

这种感觉，就像吃了五年食堂，突然自己下厨炒了个菜，虽然卖相一般，但香得一批。

这个博客就是我的第一道菜，欢迎来尝尝，也欢迎留言吐槽。

让我们一起，在写代码的路上，时不时 vibe 一下。
